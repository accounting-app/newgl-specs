# Quality audit pass (react-doctor + impeccable), Aug 2026

**Status: complete** for the scope below. A few items were deliberately deferred rather than fixed -- see "Deferred, on purpose" at the end.

Branch: `quickslike#26-issue_ui_ux_updates_fixes_dc`.

## What this was

Two tools, run as a baseline-then-fix pass over `quickslike`, followed by a related fix for loading-state UX the tools don't check for:

- **[react-doctor](https://github.com/millionco/react-doctor)** (`npx react-doctor@latest`) -- a deterministic static analyzer: state/effects misuse, performance, accessibility, unused code, dead files. Score went from **39/100 → 43/100** on the full repo (174 → 136 issues); every file actually touched in this pass scores 100/100 on its own.
- **[impeccable](https://github.com/pbakaus/impeccable)** -- a Claude Code design-guidance skill. Installed locally (gitignored, not shared via git -- see quickslike's `.gitignore`), used for `/impeccable audit` passes surface-by-surface. It also generates `PRODUCT.md` and `DESIGN.md` at the `quickslike` project root, both local-only for now; **not committed to this specs repo**, since they're living, tool-managed files that get regenerated by future audit runs rather than hand-edited plan docs.

## What got fixed

Ordered roughly the way it was actually done -- see the branch's commit history for exact diffs.

1. **react-doctor high-confidence findings**: an impure state updater (`toggleSplitMode` called `setDraftSplits` inside `setIsSplitMode`'s updater function -- React may invoke updaters more than once), two auth pages missing `try/catch/finally` around Supabase calls (an unhandled exception left the submit button stuck disabled forever with no error shown), 3 confirmed-dead files, and the unused `codemirror` dependency (superseded by the individual `@codemirror/*` packages actually imported).
2. **`--color-negative` design token**, added to all 5 themes (light/dark/modern/america250/pretty), replacing 57 hardcoded `text-red-600` instances across 28 files. Also fixed the create-file boilerplate echoing the active company's own (possibly non-English) label into a new file's `option "title"` -- now a fixed `"New Ledger"` placeholder.
3. **Global nav** (`CompanyPicker`, `TopHeader`): a real ARIA bug (`role="menuitem"` was on a `<div>` wrapping two separately-focusable buttons), a wrong semantic button color, and both header dropdown menus missing Escape-to-close entirely.
4. **Reports**: `ReportAccountRows`/`ReportSection` (shared across every report page) had zero keyboard access on their row-expand and drill-down interactions -- a full keyboard lockout on the whole Reports section, not just an AAA nice-to-have.
5. **Modals**: both modal patterns in the app (`ui/modal.tsx` and the CSV-import confirm dialog) were missing `role`/`aria-modal`/Escape entirely, then given a real focus trap (new shared `src/hooks/use-focus-trap.ts`) once the basic semantics were in place.
6. **All Apps flyout** -- the flagship item. It only opened on mouse hover, no focus equivalent at all: tabbing to "All apps" and pressing Enter navigated straight to the first item of the first category, with every other item in that category (e.g. Bank Rules under Accounting) completely unreachable via keyboard, even though the destination pages exist. Fixed with focus/blur-capture on the trigger wrapper (`SideNav`) and focus-triggered sub-panels inside `AppsFlyout`, mirroring the existing hover-intent behavior.
7. **Status-color token family**: `--color-positive`/`--color-info`/`--color-warning-*`, added to all 5 themes. Mostly extraction, not invention -- the actual colors (emerald/amber/sky) were already hardcoded throughout `dashboard-metrics.tsx` and `toast-viewport.tsx`; this just named them and applied the same "stoplight colors stay consistent across themes, unlike brand-accent colors" rule the existing `--bean-accent-2/3` and `--color-negative` tokens already established. Fixed a concrete bug in the process: the dashboard's "Needs attention" banner used Tailwind's `dark:` variant instead of the app's real `.dark`/`.modern`/`.america250`/`.pretty` theming system, so it silently fell back to light-mode amber in three of the five themes.
8. **Bank rules**: a `key={index}` on the draft-condition list, replaced with a stable per-row `clientId` (no bug today since every field is fully controlled, but a real one waiting to happen on removal).
9. **Register cluster** (`table-pagination.tsx`, `filter-form-popover.tsx`, `reconcile-status.tsx`, `register-table.tsx`): fake `<a href="#">` pagination controls (one of which was a literal no-op on click), 7 unlabeled filter fields (fixed by using `InputField`/`SelectField`'s existing `label` prop, no shared-component changes needed), an unreachable-by-keyboard reconcile-status cell, two unkeyboardable clickable table rows, and 3 raw `<select>` elements in `CompanyPicker` migrated to the already-mature `SelectField` component. Deliberately did **not** touch `register-table.tsx`'s internal state management (17 `state-adjust-on-prop-change` instances, effect chains, a `useReducer` migration) -- that's real behavioral-risk refactoring belonging to `plans/ui/UI_DESIGN_SYSTEM_PLAN.md`'s Stage 5 (register cluster, sequenced last, highest complexity), not this audit pass.
10. **Security**: a real open-redirect risk in the `?next=` param used by both the login page's client-side redirect and `auth/callback/route.ts`'s server-side one after exchanging the Supabase auth code. New `src/lib/auth/safe-redirect.ts` restricts it to a same-origin relative path.
11. **Loading states** (not a react-doctor/impeccable finding -- a direct user report): `TopHeader`'s `CompanyPicker` returned `null` while loading, collapsing that side of the header to zero width and causing the avatar menu on the other side to visibly jump position once the company loaded. Fixed with a new shared `src/components/ui/skeleton.tsx` primitive and a same-footprint placeholder. Extended the same treatment to the avatar/user-email area, and to `dashboard-metrics.tsx`: replaced one blocking `Promise.all`-gated "Loading dashboard…" screen with three genuinely independent network calls (accounts, transactions, AI usage) and three independent loading flags, so e.g. the Bank Accounts card -- which only reads `accounts`, not `transactions` -- can render real data the instant that one call resolves, without waiting on the others.

## New shared primitives

- `src/components/ui/skeleton.tsx` -- loading placeholder, sized/shaped entirely via `className` (no default radius, to avoid an unpredictable Tailwind class-cascade conflict with a caller's own radius).
- `src/hooks/use-focus-trap.ts` -- standard modal focus-trap (move focus in, constrain Tab, restore focus on close), shared by both modal patterns.
- `src/lib/auth/safe-redirect.ts` -- open-redirect guard for `?next=` params.
- Design tokens: `--color-negative(-border|-subtle-hover)`, `--color-positive(-border)`, `--color-info(-border)`, `--color-warning-bg/-border/-text` -- all 5 themes.

## Deferred, on purpose

Not silently skipped -- each was reviewed and left for a stated reason:

- **`register-table.tsx`'s internal state management** (and the same category of thing in `journal-entry-modal.tsx`, `payee-side-modal.tsx`, `import-modal.tsx`, `csv-review-table.tsx`, `reports-page.tsx`, `dashboard-metrics.tsx`, `bank-rules-page.tsx`) -- belongs to `UI_DESIGN_SYSTEM_PLAN.md` Stage 5.
- **13 unused exports** in `src/modules/accounting/domain/` -- each is used internally (e.g. `z.infer<typeof X>`) but not imported elsewhere. Could be intentional public API surface or genuinely dead; needs a product call, not a mechanical `export` strip.
- **33 "zod v4 prefer top-level string formats"** findings (`z.string().email()` vs `z.email()`) -- a library API-version style preference, not a bug.
- **A BaaS-config security note** (Supabase config visible in the browser bundle) -- expected, since the real security boundary is Supabase RLS, not client-side secrecy.
- **`toast-viewport.tsx`'s success/error/info trio** and **`dashboard-metrics.tsx`'s orange "expenses" flow-direction color** -- reviewed; error got tokenized (`--color-negative`) as part of item 2/7 above, but success/info/orange are lower-priority style-consistency items, not bugs, left for a future pass.
- **`SideNav`'s hover-only flyout** was the one real gap found and then fixed (item 6 above) -- listed here only because it was flagged as deferred mid-pass before being picked back up.
